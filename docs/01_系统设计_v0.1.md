> 来源材料：岑若曦《短线的最高境界是不停的追逐涨停》量化拆解（S1–S22）

## 1. 先把原文拆成"能拼装"的零件

### 1.1 22 条规则其实只有六种性质

直接把它们当成"22 个信号"去叠加是错的——它们的**逻辑类型**根本不同。混用会导致同一个东西被计算两遍，或者两个信号互相抵消。

| 类型 | 作用 | 包含 | 能否直接产生买卖信号 |
|---|---|---|---|
| **G 门控** | 决定"今天能不能做、做多重" | S13, S22, S5(时代性), S19, S20 | 否，只做否决与缩放 |
| **U 池子** | 决定"看哪些票" | S1, S3, S4 | 否，只缩小范围 |
| **R 排序** | 决定"池子里谁优先" | S2, S14, S21 | 否，只排序 |
| **T 触发** | 决定"什么价位买" | S6, S7, S8, S10, S11 | **是**，但必须唯一 |
| **H 持仓态** | 决定"拿着还是走" | S9, S12 | 否，只改持仓状态 |
| **X 退出** | 决定"什么条件卖" | S16, S17 | **是** |

> **第一条设计原则**：一天之内，**T 类（触发）只能启用一个**。原文自己就写了"低吸的别去抢打板的饭碗，打板的别去抢低吸的肉"——这句话不是风格建议，是**系统约束**。

### 1.2 直接拼装会撞上的五类结构性冲突

| # | 冲突对 | 冲突内容 | 如果不管会怎样 |
|---|---|---|---|
| **X1** | S6 打板 ↔ S7 低吸 ↔ S8 半路 | 三种买点在**同一天同一只票**上互斥，但原文并列给出 | 同一标的收到"买"和"不买"两个信号，实盘变成主观选择 |
| **X2** | S16 快止盈 ↔ S9/S12 拿住加速 | 一边说 3–5% 就跑，一边说一致加速要拿 | 规则二选一，回测里可以事后挑，实盘做不到 |
| **X3** | S9 自身 | "分歧"既指**个股换手分歧**（买点），又指**市场情绪分歧**（卖点/减仓） | 同一个词两个方向，指标一算就反向 |
| **X4** | S2 龙头 ↔ S4 低位首板 | 同题材内一个买最高身位、一个买最低身位 | 3 个槽位被两种相反逻辑争抢，实际持仓随机化 |
| **X5** | S15 三只分仓 ↔ S3 主线集中 | 3 只全在主线上 = 伪分散 | 板块 Beta 没分散，退潮日三只一起止损 |

此外还有两类**冗余**（不是冲突，但会让信号虚高）：
- **R1** S1（涨停过）与 S6（今日涨停）共享"涨停"这个事件，重复计数；
- **R2** S2（身位）与 S21（相对强度）高度相关，同时加权等于给"强"加了双倍权重。

### 1.3 解决原则：三条

**原则一 · 分层正交（一个层级只回答一个问题）**
把 22 条规则分配到 9 个层，每层输出一种东西，层与层之间只传"允许/不允许 + 排序 + 参数"，不传方向相反的建议。

**原则二 · 单调收缩（下层只能更严，不能更松）**
这是可验证的硬不变量。任何下层规则**只能减少**暴露，不能把上层已经否决的标的救回来。

| 不变量 | 内容 | 违反示例 |
|---|---|---|
| I1 | 单票权重 ≤ min(状态仓位上限, 槽位权重, 引擎上限) | 情绪冰点却满仓一只 |
| I2 | 状态门控只能**关闭**引擎，不能**开启**被关闭的引擎 | 退潮期因为"看到好票"临时打板 |
| I3 | 止损只能上移，不能下移 | 亏了 7% 说"再等等" |
| I4 | 被 L0/L7 剔除的标的，不能被 L3/L4 重新纳入 | ST 股因"身位最高"被买入 |
| I5 | 同一标的不能被两个引擎同时持有 | 同一只票被算成两笔仓位 |

**原则三 · 引擎互斥（把"并列的策略"改成"按状态选一个"）**
S6/S7/S8 不是三个可选策略，而是**同一个"买入引擎"在三种市场状态下的三种实现**。由 L1 状态选择，不由个股选择。

## 2. 系统总架构

### 2.1 决策管线

```
                    ┌─────────────────────────────────────────┐
   全市场日线快照 →  │ L0  制度/可交易性                       │ 剔除 ST/新股/停牌/不可成交
                    └───────────────┬─────────────────────────┘
                                    ↓  可交易全集
                    ┌───────────────┴─────────────────────────┐
                    │ L1  市场状态（S13+S22）                  │ → 状态标签 + 仓位上限 + 引擎开关
                    └───────────────┬─────────────────────────┘
                                    ↓
                    ┌───────────────┴─────────────────────────┐
                    │ L2  主线方向（S3）                       │ → 主线题材集合 + 退潮题材黑名单
                    └───────────────┬─────────────────────────┘
                                    ↓
                    ┌───────────────┴─────────────────────────┐
                    │ L3  强势池 + 身位（S1+S2+S4+S14+S21）    │ → 龙头/龙二/补涨/禁买
                    └───────────────┬─────────────────────────┘
                                    ↓
                    ┌───────────────┴─────────────────────────┐
                    │ L4  买入触发（S6/S7/S8/S10/S11 三选一）  │ → 候选信号 + 成交概率
                    └───────────────┬─────────────────────────┘
                                    ↓
                    ┌───────────────┴─────────────────────────┐
                    │ L7  组合风控（S15+S18）                  │ → 下单 / 拒绝（槽位·集中度·熔断）
                    └───────────────┬─────────────────────────┘
                                    ↓  成交
                    ┌───────────────┴─────────────────────────┐
                    │ L5  持仓状态（S9+S12）→ L6 退出（S16+S17）│ → 持有/减仓/清仓
                    └───────────────┬─────────────────────────┘
                                    ↓
                    ┌───────────────┴─────────────────────────┐
                    │ L8  分析与治理                            │ → 归因·衰减监控·参数变更
                    └─────────────────────────────────────────┘
```

### 2.2 每层的契约

| 层 | 唯一职责 | 输入 | 输出 | 失败模式 |
|---|---|---|---|---|
| **L0** 制度 | 这只票今天**能不能交易** | 日线、上市日、ST 标记、涨跌停状态 | 可交易 bool + 涨跌幅制度 | 用错涨停幅度 → 全盘信号失真 |
| **L1** 状态 | 今天**能不能开仓、开多重** | 全市场涨跌停/breadth 统计 | 状态标签 + 总仓位上限 + 引擎白名单 | 状态天天跳变 → 等于没做状态管理 |
| **L2** 方向 | **做哪个题材** | 板块成分、板块涨停数、成交额 | 主线集合 + 黑名单 | 追已退潮题材 |
| **L3** 标的 | 题材内**买谁** | 涨停事件、封板质量、位置 | 分级标签 + 排序 | 买中间身位跟风 |
| **L4** 触发 | **什么价位买** | 竞价/分时/封单 | Signal 对象 | 假设不可成交 |
| **L5** 持仓 | 手里这只**是什么状态** | 换手、量比、封板方式 | 状态标签 | 状态判定滞后于价格 |
| **L6** 退出 | **什么条件卖** | 成本、现价、状态、均线 | 卖出指令 | 快止盈与拿住加速打架 |
| **L7** 组合 | 整个账户**冒多大风险** | 现有持仓、当日盈亏 | 下单/拒绝 | 伪分散 |
| **L8** 分析 | **系统还健康吗** | 逐笔账本 | 归因报告 + 降仓/停用 | 用总收益掩盖单引擎失效 |

### 2.3 S1–S22 到层的映射（谁在哪一层干活）

| 层 | 主用 | 辅助/过滤 | 明确不用 |
|---|---|---|---|
| L0 | — | — | S5 次新（衰减，仅作 +分） |
| L1 | **S13** | S22 拥挤度、S21 仅作参考 | S19/S20（理念，见 §11） |
| L2 | **S3** | S22 | — |
| L3 | **S1 S2 S4 S14** | S21 | — |
| L4 | **S6 S7 S8 S10 S11** | S12（换手健康度，作过滤） | — |
| L5 | **S9 S12** | — | — |
| L6 | **S16 S17** | — | — |
| L7 | **S15 S18** | S13（仓位映射） | — |
| L8 | **S18** | S20（执行偏差） | — |

## 3. L0 制度与可交易性层

这一层不做任何"选股"，只做**剔除**。它必须最先执行，因为所有后续指标都依赖正确的涨停价。

### 3.1 涨停幅度表（必须按标的属性逐票判定）

| 板块 | 代码前缀 | 幅度 | 备注 |
|---|---|---|---|
| 主板 | 60/00 | 10% | |
| 创业板 | 30 | 20% | 2020-08-24 起 |
| 科创板 | 688 | 20% | |
| 北交所 | 8/4 | 30% | 流动性差，默认剔除 |
| ST/\*ST | 任意 | 5% | 默认剔除 |
| 新股 | 上市 ≤ 5 日 | 无限制/44% | 默认剔除 |

```
limit_price(t) = round(prev_close(t-1) × (1 + limit_ratio(t)), 2)   # 四舍五入到分
is_limit_up(t) = close(t) >= limit_price(t) - 1e-6
is_yizi(t)     = open(t) == limit_price(t) and low(t) == limit_price(t)
```

> 注意：**涨停价要按"分"四舍五入**，不同板块的舍入规则会导致 0.01 的误差，足以让"是否涨停"判断翻转。这是最容易被忽略、又最影响结果的一个细节。

### 3.2 剔除清单

| 剔除项 | 理由 |
|---|---|
| ST / \*ST | 5% 幅度，价格行为不可比 |
| 上市 < 60 交易日 | 无 250 日位置分位，且次新溢价时代已过（S5 衰减） |
| 停牌 / 复牌首日 | 价格不连续 |
| 北交所 | 流动性不足，滑点吃掉全部边际 |
| 当日跌停封死 | 想卖也卖不出，不能作为候选 |
| 拟退市 / 面值低于 1 元 | 尾部风险不对称 |

### 3.3 T+1 与不可成交约束（写进回测/实盘同一套规则）

```
买入当日不可卖出
卖出时若跌停封死(seal_amt_down > 0 且 low == limit_down) → 顺延至下一可成交日
跌停打开后按打开价成交，而非跌停价
```

这条约束会显著改变结果：原文 2020-02-03「3100 只跌停」的场景下，**止损价是不可执行的**。任何假设"跌到 -5% 就一定能卖"的回测都是错的。

## 4. L1 市场状态层（S13 + S22）

### 4.1 为什么必须做这一层

原文最核心的判断是"情绪是本，技术形态是末"。但原文给的是**固定阈值**（"涨停家数 > 150~200 就是高潮"）。这在 2015 年（约 2800 只票）和 2024 年（约 5300 只票）完全不可比。

**解法：全部转成滚动分位数，不用绝对值。**

### 4.2 E-score：情绪温度计

七个原始因子：

| 因子 | 定义 | 代表什么 |
|---|---|---|
| `f1` 涨停家数 | 当日涨停（剔除 ST/新股） | 攻击面宽度 |
| `f2` **连板晋级率** | 昨日涨停今日仍涨停家数 ÷ 昨日涨停家数 | **赚钱效应（最核心）** |
| `f3` 封板成功率 | 1 − 炸板数/(涨停数+炸板数) | 承接力度 |
| `f4` 最高连板高度 | max(board_count) | 空间天花板 |
| `f5` 涨跌家数比 | log(上涨家数/下跌家数) | 广度 |
| `f6` 量能比 | 全市场成交额 ÷ 20 日均值 | 增量资金 |
| `f7` **昨日涨停股今日均涨幅** | mean(ret of 昨日涨停股) | **打板直接收益（最直接）** |

```
E_raw = mean( pct_rank(f_i, window=252) for i in 1..7 )   # 等权，不调权重
E     = round(E_raw × 100)
```

**为什么等权？** 因为调权重就是增加 6 个自由度。在还没验证策略有效性之前，调权重只会把噪声拟合进去。等权是最保守的起点（这也让 L1 的参数从 7 个降到 0 个）。

> `f2` 和 `f7` 是原文没有明确写出、但最该补的两个因子。原文用"情绪"这个词，`f7`（昨天打板的人今天赚不赚钱）才是这句话最直接的量化。

### 4.3 状态定义（五状态 + 迟滞）

状态的判定**有优先级**（从上往下，命中即停），这样避免规则打架：

| 优先级 | 状态 | 进入条件 | 语义 |
|---|---|---|---|
| 1 | **FADE 退潮** | 上一状态 ∈ {EXPAND, DIVERGE} 且（E < 40 或 炸板率 5 日升 > 12pp 或 最高板高度较 5 日高点回落 ≥ 2） | 赚钱效应崩塌，**空仓** |
| 2 | **ICE 冰点** | E ≤ 22 且 ΔE(5日) ≤ +5 | 无人赚钱，等反抽 |
| 3 | **EXPAND 主升** | E ≥ 65 且 f2 ≥ 0.45 且 f4 ≥ 4 | 最强攻击窗口 |
| 4 | **DIVERGE 高位分歧** | E ≥ 50 且（f3 较 5 日均值下降 > 20% 或 f4 < f4_ma5 × 0.8） | 还能做，但要降仓 |
| 5 | **REPAIR 修复** | 其余情况 | 试错期，小仓 |

**迟滞规则**（防止天天跳变，这是可行性的硬要求）：
```
状态切换需满足：连续 min_dwell = 2 个交易日满足新状态条件
E 的边界带 ±5：例如 EXPAND 进入需 E ≥ 65，退出需 E < 60
```

### 4.4 状态 → 仓位与引擎（这是"组合"的核心表）

| 状态 | 总仓位上限 | 主导引擎 | 允许开仓引擎 | 单票上限 | 说明 |
|---|---|---|---|---|---|
| **ICE 冰点** | 20% | E2 低吸 | E2（半仓） | 10% | 只做高辨识度龙头的确认性反弹 |
| **REPAIR 修复** | 50% | E2/E3 | E2, E3 | 20% | 做低位补涨与 1 进 2 |
| **EXPAND 主升** | 100% | **E1 接力** | E1, E3 | 33% | 唯一可以打板/接力的窗口 |
| **DIVERGE 分歧** | 50% | E2 低吸 | E2 | 20% | 只低吸不追高，已有 E1 仓位只减不加 |
| **FADE 退潮** | **0%** | — | 无 | 0% | 清仓，等下一个冰点 |

> **这张表就是"方法搭配"的答案**：不是把 S6/S7/S8 都打开，而是让状态决定开哪一个。
> 读法：EXPAND 期 E1 的期望收益最高，DIVERGE 期 E1 的期望为负——所以"DIVERGE 期能不能打板"这个问题，答案是**不能，且这不是风格问题，是纪律问题**。

### 4.5 一个必须点破的命名陷阱（对应冲突 X3）

原文里"分歧"出现了两种完全相反的含义：

| 用法 | 指什么 | 方向 |
|---|---|---|
| S9「买在分歧」 | **个股/板块层面**的高换手、炸板回封、长上影 | **买**（健康的换手） |
| S13「情绪分歧期」 | **全市场层面**的赚钱效应转弱、炸板率上升 | **卖/减仓** |

**这两个不是一回事。** 个股分歧（充分换手）往往是好事，市场分歧往往是坏事。

> 系统里的硬约定：`DIVERGE` 专指**市场状态**；个股层面的分歧只作为 L5 的 `HELD_DIVERGENT` 标签，绝不作为买入理由单独使用。

## 5. L2 主线方向层（S3）

### 5.1 主线评分

```
heat(board, t)     = 板块内涨停家数(t)
heat_rank(board,t) = pct_rank(heat, window=10)          # 滚动分位，不用绝对值
money_share(board) = 板块成交额 / 全市场成交额
new_flag(board,t)  = heat(board,t) 首次突破其 60 日 90 分位
```

```
main_line(t) = { board | heat_rank ≥ 0.70 且 板块内存在 board_count ≥ 2 的标的 }
```

### 5.2 新旧切换（原文两条铁律的量化）

```
if new主题 当日涨停数 ≥ 8 且 heat_rank ≥ 0.95:
    老主线降级为 "退潮题材"，进入黑名单
    黑名单题材内只允许保留 1 只"活口"（当日仍涨停且封板最早的那只）
```

### 5.3 这一层最大的风险（必须承认）

原文说"只做科技与新能源"，这是**后验归因**——2019–2020 年确实是这两条线。如果把它写成硬规则，等于把 2020 年的答案抄到 2026 年。

**所以 L2 不做"指定行业"，只做"当期热度排序"。** 哪个板块热就做哪个，不预设答案。

## 6. L3 标的层（S1 + S2 + S4 + S14 + S21）

### 6.1 强势池（S1）

```
strong_pool(t) = { s | 近 20 个交易日内至少 1 次涨停 }
```
这一步只是**缩小范围**，不产生买入信号。它的作用是把 5000 只票降到约 300–600 只。

### 6.2 身位分级（S2 + S14）

```
board_count(t) = is_limit_up(t) ? board_count(t-1) + 1 : 0

identity(s, t) = 0.40·z(board_count)
               + 0.25·z(-first_seal_minutes)        # 封板越早越强
               + 0.20·z(seal_amount / float_mv)     # 封单占流通市值
               + 0.15·z(turnover)                   # 龙头常高换手

题材内排名：
  rank 1 → 龙头      可买
  rank 2 → 龙二      可买（半仓）
  board_count == 1 且 低位低价 → 补涨候选（走 E3）
  其余   → 跟风      **禁买**
```

### 6.3 高低切闸门（S14）

```
if max_board(全市场) ≥ 6:
    禁止买入 board_count ∈ [2, max_board-1] 的标的     # 中位身位，最危险
    只允许：board_count == 1（1进2）或 绝对龙头
```

这条规则解决冲突 X4：**龙头（E1）和低位首板（E3）不会同时抢仓位**——由 `max_board` 决定当前该做哪一个。

### 6.4 过滤项

| 过滤 | 规则 | 依据 |
|---|---|---|
| 低价 | close ≤ 10 元（E3 专用） | S4 |
| 低位 | close / max(close, 250日) ≤ 0.60 | S4 |
| 相对强度 | 20 日超额收益 > 0 且不在跌幅榜前 10% | S21 |
| 次新 | 上市 60–365 日 → identity +0.05 分（不加规则） | S5 衰减，只作微调 |

## 7. L4 买入层：三个引擎（这是整套系统的心脏）

### 7.1 为什么是"引擎"而不是"策略池"

原文把 S6/S7/S8 并列成三种战法，读者自然会想"哪个好就用哪个"。这个想法在实盘里是灾难：**你总能在事后找到"今天该用打板"的理由**。

改成引擎后，逻辑变成：
```
市场状态 → 决定唯一引擎 → 引擎决定触发条件 → 触发条件决定买点
```
**你不能在盘中改引擎，就像你不能在开车时改目的地。**

### 7.2 三个引擎的完整契约

| | **E1 接力引擎**（S6+S10） | **E2 低吸引擎**（S7+S11） | **E3 首板引擎**（S4+S8+S14） |
|---|---|---|---|
| **风格** | 追强 | 抄弱转强 | 做扩散 |
| **适用状态** | EXPAND | ICE / REPAIR / DIVERGE | REPAIR / EXPAND |
| **票池** | 昨涨停、board_count ≥ 2、身位 rank ≤ 2 | 近 10 日有涨停、曾 ≥ 2 板、昨日炸板或跌 ≥ 3% | 昨日首板、∈主线、低价低位 |
| **买入触发 A** | 强更强：gap ≥ +3% 且 竞价量比 ≥ 1.2 | gap ≤ −3% 且 开盘 30 分钟不创新低且站上均价 | gap ∈ [+2%, +6%] 且 量比 ≥ 1.2 |
| **买入触发 B** | 弱转强：gap ∈ [−5%, 0) 且 30 分钟内翻红 | （同上，唯一触发） | — |
| **否决条件** | 强转弱：gap ≥ +5% 但竞价量比 < 0.8 | gap ≤ −7% 视为趋势走坏，放弃 | gap > +6%（一致性过高，易一字） |
| **止盈** | 8% | 5% | 6% |
| **止损** | −5% | −4% | −4% |
| **最长持有** | 3 日 | 2 日 | 2 日 |
| **数据要求** | 日线 + 竞价快照 | 日线 + **分时（必须）** | 日线 + 竞价快照 |
| **单票上限** | 33% | 20% | 25% |

### 7.3 为什么 E1 的止盈从 3% 改成 8%（这是最重要的参数改动）

原文 S16 主张"3–5% 快兑现"。但算术上：

| 止盈/止损 | 保本胜率 | 45% 胜率下的期望 |
|---|---|---|
| 3% / 5% | **66.3%** | −1.70% |
| 5% / 5% | 53.0% | −0.80% |
| 6% / 4% | 43.0% | +0.20% |
| **8% / 5%** | **40.8%** | **+0.55%** |
| 10% / 5% | 35.3% | +1.45% |

**3%/5% 结构需要 66% 胜率才保本。** 而且要命的是 T+1：3% 的止盈当日拿不到，次日跳空会吃掉 10–20%，实际到手 2.4–2.7%，保本线被推到 **69–72%**。

> 这不是说原文错了——原文的 70% 胜率配上 3%/5% 恰好是保本的。问题在于**它把全部安全边际压在了"70% 胜率"这一个未经证实的假设上**。
> 一旦真实胜率是 55%（打板策略的现实水平），整条路径立刻转负。
>
> 改成 8%/5%，保本线降到 41%，**即使胜率只有 45% 仍有正期望**。代价是回撤变大、胜率变低——但这才是可存活的形状。

### 7.4 成交可行性闸门（S6 偏差的解法）

原文最诚实的警告是："回测若假设涨停价必成交，会系统性高估收益。"

所以 L4 的输出**不只是信号，还有成交概率**：

| 板型 | 特征 | fill_prob | 系统处置 |
|---|---|---|---|
| 一字板 | open == high == low == limit | 0.00 | **不交易**（买不进，次日溢价与你无关） |
| 秒板 | 首次封板 ≤ 9:35 且开板 0 次 | 0.05 | **不交易**（同上） |
| 换手板 | 封板 > 10:00 或开板 ≥ 1 次 | 0.35 | 可交易（E1 主战场） |
| 炸板回封 | 触板→开板→再封 | 0.60 | 优先（有真实的换手与承接） |
| 次日竞价 | 次日开盘/集合竞价 | 0.95 | 首选（无成交假设问题） |

**设计决策：E1 不打"封死不开"的板，只做「换手板」或「次日竞价」。**

这条决策牺牲了最漂亮的那种板（一字连板），换来的是**回测与实盘的一致性**。原文的 S6 之所以危险，正是因为它把最赚钱、最买不进的样本全算了进去。

> 副作用：若某个市场阶段 80% 的涨停都是一字/秒板，E1 的票池会被抽干，引擎自动休眠。这是**正确行为**，不是 bug。

### 7.5 统一的 Signal 契约（层层传递的唯一数据结构）

```yaml
signal:
  date: 2026-11-03
  code: "600000"
  engine: E1                 # 唯一，不可为空
  regime: EXPAND             # 入场时的市场状态（用于归因）
  theme: "半导体"
  board_count: 3
  identity_rank: 1           # 题材内身位排名
  entry_type: 竞价           # 竞价 | 打板 | 低吸 | 半路
  entry_price: 12.34
  fill_prob: 0.95            # 成交概率，<0.3 直接丢弃
  tp: 0.08
  sl: -0.05
  max_hold: 3
  position_target: 0.333
  risk_budget: 0.0167        # = 0.333 × 0.05，单笔最大组合损失
  gates_passed: [L0, L1, L2, L3, L4, L7]
  reject_reasons: []
```

## 8. L5 持有层（S9 + S12）

### 8.1 持仓状态机

持仓不是"买了就等止盈止损"，它有自己的生命周期：

```
                    ┌──────────────┐
        买入 ─────→ │ HELD_OPEN    │  刚建仓
                    └──────┬───────┘
                           ↓ 收盘评估
              ┌────────────┼────────────┐
              ↓            ↓            ↓
     ┌────────────┐ ┌────────────┐ ┌────────────┐
     │HELD_WEAK   │ │HELD_       │ │HELD_ACCEL  │
     │(走弱)      │ │DIVERGENT   │ │(缩量加速)  │
     └─────┬──────┘ │(分歧换手)  │ └─────┬──────┘
           │        └─────┬──────┘       │
           ↓              ↓              ↓
       立即离场      按引擎TP/SL   减半+跟踪止盈
```

### 8.2 状态判定（每日收盘算一次，优先级从上到下）

| 状态 | 判定条件 | 语义 |
|---|---|---|
| **HELD_WEAK** | 炸板 或 close < MA5 或 当日收阴且跌破分时均价 | 强转弱，走 |
| **HELD_ACCEL** | vol_ratio < 0.8 且 换手率连续 3 日下降 且（一字 或 封板 < 9:45） | 一致加速，赶顶风险 |
| **HELD_DIVERGENT** | 其余（有换手、未加速、未走弱） | 健康分歧，拿住 |

> 注意 **HELD_ACCEL 不是坏状态**，它可能是主升最猛的一段。所以处置方式不是"卖"，而是"卖一半、留一半用跟踪止盈"——这是把 S9 的"卖在一致"翻译成可执行动作。

### 8.3 换手健康度（S12 作为过滤器，不作为买卖信号）

```
healthy_turnover = turnover ≥ 15% 且 换手率未连续下降
risk_flag        = vol_ratio < 0.8 且 换手率连降 3 日
```
`risk_flag` 只做一件事：**把单票权重砍半**。它不直接产生卖出信号——因为原文自己承认"纯缩量判断会过早卖出真龙"。

## 9. L6 卖出层（S16 + S17）

### 9.1 状态相关退出梯度（冲突 X2 的解法）

| 持仓状态 | 止盈规则 | 止损规则 | 时间规则 |
|---|---|---|---|
| **HELD_DIVERGENT** | 固定 TP（E1 8% / E2 5% / E3 6%） | 固定 SL（−5% / −4% / −4%） | 到期无条件离场 |
| **HELD_ACCEL** | **不设固定 TP**；次日高开 ≥ +5% 卖一半；剩余用「收盘 < 前日收盘」或「破 MA5」离场 | 同上 | 不设时间限制（趋势未破就拿着） |
| **HELD_WEAK** | 立即全部离场，不等价位 | 立即 | — |

**优先级（绝对不可违反）**：
```
硬止损 > HELD_WEAK 离场 > 状态止盈 > 时间止盈
```
即：**任何状态下，亏损达到止损位就无条件卖出。** 这一条覆盖 S16/S9 的所有分歧。

### 9.2 为什么这样就消除了冲突

- S16 的"快兑现"→ 只作用于 `HELD_DIVERGENT`（还没加速、没有趋势可拿）
- S9 的"卖在一致"→ 只作用于 `HELD_ACCEL`（已经在加速，固定止盈会卖飞）
- S17 的"硬止损"→ 全局最高优先级，不受状态影响

同一只票在不同时间处于不同状态，规则自动切换，**不需要人做判断**。

### 9.3 涨跌停不可卖

```
if 跌停封死 and 今日需卖出:
    标记 pending_exit，顺延至首个可成交日
    按该日开盘价成交（不能假设跌停价成交）
```

## 10. L7 组合层（S15 + S18）

### 10.1 槽位与权重

```
slots = 3
weight_i = min(0.333, regime_cap / 当前持仓数, engine_cap)
```

**关键修正**：33% 不是"设定值"，是"上限"。算术上 33% 单票 ≈ 满凯利，只有在实测胜率 ≥ 60% 时才成立（见 §14）。所以：

| 实测胜率（L8 滚动 60 笔） | 单票上限 | 满仓槽位数 |
|---|---|---|
| ≥ 60% | 33% | 3 |
| 50–60% | 25% | 4 |
| 40–50% | 20% | 5 |
| < 40% | 0（停用该引擎） | — |

> 这让仓位变成**测量出来的**，而不是拍出来的。原文的"3:3:3"作为默认值保留，但由 L8 动态校准。

### 10.2 题材集中度（解决 X5 伪分散）

```
同一题材持仓数 ≤ 2
若 3 个槽位中有 2 个同题材 → 第 3 个必须跨题材或留现金
```

### 10.3 熔断

| 触发 | 动作 |
|---|---|
| 当日组合收益 < −3% | 次日禁止开新仓 |
| 净值回撤 ≥ 8% | 总仓位上限砍半 |
| 净值回撤 ≥ 12% | 强制停 5 个交易日，人工复核 |
| 连续 3 日净值新低 | 引擎降级为观察模式（只记录不下单） |

### 10.4 年交易笔数预算（反直觉但最重要的一条）

```
年化成本拖累 = 年笔数 × 单票权重 × 单笔摩擦
```

| 年交易笔数 | 成本拖累（3 槽位，0.30% 摩擦） | 占 25% 目标年化 |
|---|---|---|
| 50 | 5.0% | 20% |
| 80 | 8.1% | 32% |
| 100 | 10.1% | **40%** |
| 150 | 15.1% | 60% |
| 300 | 30.2% | 121% |

**结论：若目标是 25% 年化，年交易笔数应 ≤ 83 笔（约每周 1.6 笔）。**

这直接否定了 S18 "高周转靠复利"的路径。复利的前提是单笔边际足够厚；当单笔期望只有 0.5%、摩擦却有 0.3% 时，**周转是把利润交给券商**。

> 原文说"10 天做 10 个 3% 比 10 天赚 30% 更好"，数学上是对的（1.03^10 = 1.344）。
> 但那个算式漏了摩擦：10 次交易扣掉 0.3%×10 = 3%，实际是 1.027^10 = 1.305，已经不如一次性 30%。
> **原文的复利论证在小止盈+高周转下不成立。**

## 11. L8 分析层

### 11.1 逐笔账本（每条交易必须记录）

| 字段 | 用途 |
|---|---|
| 入场 regime / 引擎 / 题材 | 归因的主维度 |
| 信号价 vs 成交价 | 滑点归因 |
| 理论 fill_prob vs 实际是否成交 | 验证成交模型 |
| 持仓状态路径（如 OPEN→DIVERGENT→ACCEL） | 判断退出规则是否被正确触发 |
| 退出原因（TP / SL / WEAK / TIME / 跌停顺延） | 判断哪条规则在赚钱 |
| 持有天数、单笔收益、组合贡献 | 复利路径 |

### 11.2 核心监控矩阵（引擎 × 市场状态）

这张表决定**下周开哪些引擎**：

| | ICE | REPAIR | EXPAND | DIVERGE | FADE |
|---|---|---|---|---|---|
| **E1** | — | — | 主战场 | 禁止 | — |
| **E2** | 半仓 | √ | — | √ | — |
| **E3** | — | √ | √ | — | — |

每月统计每个格子的 `样本数 / 胜率 / 盈亏比 / 期望`，**如果某格样本 < 20 笔，不得据此调参**（否则就是在拟合噪声）。

### 11.3 衰减监控（Wilson 下界）

```
rolling_win_rate_60 = 最近 60 笔胜率
wilson_lower = Wilson 下界（95%）
if wilson_lower < 保本胜率:
    该引擎降级为观察模式
if 连续 100 笔 wilson_lower < 保本胜率:
    停用该引擎，回到设计阶段
```

用 Wilson 下界而不是点估计，是因为 20 笔的 50% 胜率和 200 笔的 50% 胜率，可信度差一个数量级。

### 11.4 执行偏差（S20 的量化映射）

| 指标 | 定义 | 阈值 |
|---|---|---|
| 漏单率 | 应下单未下单 / 应下单 | < 5% |
| 滑点中位数 | (成交价−信号价)/信号价 | < 0.15% |
| 改单率 | 盘中修改止损/止盈次数 / 交易数 | = 0 |
| 规则外交易 | 不在信号列表里的交易笔数 | = 0 |

**改单率必须是 0。** 只要出现一次"这次例外"，整套系统的统计基础就失效了——因为回测里没有"例外"这个变量。

### 11.5 参数治理

- 每季度**最多**修改 1 个参数
- 修改必须附带"改前/改后"的假设与预期影响
- 参数变更需记录在 `config/CHANGELOG.md`
- **禁止**在回撤期调参（这是最常见的自毁方式）

## 12. 一天的完整运行时序

```
══════════ 盘前 08:30 ══════════
1. 更新日线（T-1 收盘）
2. L0: 计算全市场可交易集 + 涨停幅度 + 昨涨停列表
3. L1: 计算 E-score → 状态判定（含迟滞/最小驻留）
4. L2: 计算主线集合 + 黑名单
5. L3: 构建强势池 → 身位分级 → 禁买清单
6. L4: 按状态选定唯一引擎 → 生成"观察名单"（含具体触发价位与阈值）
7. L7: 读取当前持仓与净值 → 计算今日可用槽位与风险预算

══════════ 集合竞价 09:15–09:25 ══════════
8. 抓竞价快照：gap、竞价量、竞价金额
9. 对观察名单逐票判定触发 A / 否决条件
10. 命中 → 生成 Signal（含 fill_prob）→ L7 风控复核 → 下单

══════════ 开盘 09:30–10:00 ══════════
11. E2 专用：30 分钟分时确认（不创新低 + 站上均价）
12. E1 弱转强分支：翻红确认后买入
13. 记录所有成交与未成交（未成交要记原因，用于校准 fill_prob）

══════════ 盘中 10:00–14:50 ══════════
14. 持仓监控：是否触及硬止损（无条件执行）
15. 是否出现 HELD_WEAK（炸板/破 MA5）→ 离场
16. HELD_ACCEL → 次日高开卖半仓的挂单准备
17. 禁止开新仓（除 E1 接力分支外），禁止改单

══════════ 收盘后 15:30 ══════════
18. 更新持仓状态机（WEAK / ACCEL / DIVERGENT）
19. 执行时间止盈、状态止盈
20. 记账：每笔的完整字段
21. L8: 更新滚动胜率、Wilson 下界、滑点统计
22. 熔断检查：当日收益 < −3% → 次日禁开仓
23. 输出"明日观察名单"（引擎由明日状态决定，暂不预设）

══════════ 盘后复盘（每周） ══════════
24. 引擎×状态矩阵更新
25. 检查是否有"规则外交易"
26. 检查 fill_prob 校准误差
```

> 注意第 6 步和第 23 步：**引擎选择发生在盘前，不发生在盘中**。这是 S19「只追随，不预测」最硬的落地方式——你连"今天用哪个战法"都不能临时决定。

| L5 | 缩量量比 | 0.80 | ✔ |
| L5 | MA 周期 | 5 | ✘ |
| L6 | E1/E2/E3 止盈 | 8% / 5% / 6% | ✔✔✔ |
| L6 | E1/E2/E3 止损 | −5% / −4% / −4% | ✔✔✔ |
| L6 | 最长持有 | 3 / 2 / 2 日 | ✘ |
| L6 | 加速减半阈值 | +5% | ✘ |
| L7 | 槽位数 | 3（按实测胜率 3–5） | ✘ |
| L7 | 单票上限 | 33% | ✘（由 L8 动态校准） |
| L7 | 同题材上限 | 2 | ✔ |

**自由度预算**：22 个可调参数 × 每参数 30 笔样本 = **至少 660 笔交易**才能可靠调参。按 150 笔/年计算 = **4.4 年**。

> 这个数字是残酷但必要的：它说明在头两年，**你不该调参，只该验证**。

## 14. 可行性验证结论

完整数据见 `02_可行性验证报告.md`，下面是四类检验的结论。

### 14.1 结构可行性：通过

| 检验 | 结果 |
|---|---|
| 五类冲突是否已消除 | X1→引擎互斥；X2→状态退出梯度；X3→命名分离；X4→高低切闸门；X5→题材上限 |
| 单调收缩不变量 I1–I5 | 全部可编码为断言（见 §1.3） |
| 是否存在死状态 | 无：每个状态都有明确的进入/退出/仓位 |
| 状态驻留是否够长 | 建议矩阵下平均 4.3 天，最短 3.1 天（＞持仓周期 2–3 天） |

### 14.2 算术可行性：部分通过，且发现了原文的核心问题

| 检验 | 原文参数组 | v0.1 |
|---|---|---|
| 保本胜率 | **66.3%**（且 T+1 后 69–72%） | **40.8%** |
| 45% 胜率下的单笔期望 | **−1.70%** | **+0.55%** |
| 33% 仓位所需胜率（满凯利） | **77.5%** | 60.5% |
| 年化成本上限 | 约 300 笔 → 30% 拖累 | ≤ 83 笔 → 8% 拖累 |

**最重要的发现**：原文「3% 止盈 + 5% 止损 + 70% 胜率」这组假设**在数学上完全自洽**——但它只支持 **11%** 的单笔仓位。

**问题出在 3:3:3**：单票 33% 是 11% 的 3 倍，等价于要求 **77.5%** 的胜率。也就是说，即便在作者自己的假设下，仓位也是超配的。

这也解释了原文为什么把"心态"放在第一位：**在这个仓位下波动必然剧烈，不靠纪律拿不住。**

→ 这就是为什么 v0.1 把 E1 改成 8%/5%：**用更低的胜率要求，换取真实存在的那一点点边际。**

### 14.3 组合可行性（合成路径压力测试）：可存活，但门槛明确

在不假设任何行情数据的前提下，用合成路径检验 3 槽位组合。关键数字（1500 条路径 × 500 交易日）：

| 指标 | 结果 |
|---|---|
| 零边际下的单笔期望 | **−0.31%**（正好等于摩擦 0.30% → 模型自洽） |
| **保本所需单笔毛收益** | **+0.34%** |
| 84 笔/年周转下的保本线 | +0.35%（几乎相同） |
| 摩擦 0.15% 时的年化 | **+3.6%** |
| 摩擦 0.30% 时的年化 | −8.2% |
| 摩擦 0.50% 时的年化 | **−21.4%** |
| 守纪律 vs 无纪律 | −8.2% vs −16.1%（**纪律值 8pp/年**） |
| 3 槽位 P(回撤 > 30%) | **72.9%** |
| 5 槽位 P(回撤 > 30%) | 47.1% |

**三个必须记住的结论：**

1. **保本线是"单笔"属性，不是"总量"属性。** 压低周转不能降低每笔要赚多少，只能降低总共要赚多少。低频救不了一个负边际策略，但能让正边际策略活下来。
2. **杠杆排序：摩擦 > 周转 > 槽位数 > 纪律。** 把摩擦从 0.50% 压到 0.15%，效果超过任何选股技巧。
3. **纪律不是道德问题。** 做负边际的（状态×引擎）单元，一年就值 8 个百分点。

> 完整推导、模型偏差修正（同日双触的布朗桥解）与全部情景见 `02_可行性验证报告.md` §10。

### 14.4 自由度可行性：不通过（诚实结论）

22 个可调参数 vs 每年约 150 笔样本 → 需要 4.4 年才能可靠调参。

**这不是设计缺陷，是这类策略的固有约束。** 应对方式：
1. 前 2 年**冻结所有参数**，只做验证与记录
2. 只在"参数敏感性平台区"内取值（改 ±10% 结果不变的区间才是稳健的）
3. 用样本外时段（2021 年后）验证，而不是在 2015–2020 上优化

## 15. 已知未闭合的问题

诚实地列出——这些不是"待办"，是**可能推翻整个方案的风险点**：

| # | 问题 | 影响 | 当前处置 |
|---|---|---|---|
| **O1** | 胜率到底是多少？没有任何数据支撑 | 决定仓位与是否值得做 | 用 L8 实测反解仓位，不预设 |
| **O2** | 18 个交易日的样本外期太短，不足以判断衰减 | 可能整套已失效 | 先做 3 个月影子盘（只记录不下单） |
| **O3** | 分时数据（L2 行情）能否稳定获得 | E2 引擎完全依赖它 | 若无分时，**E2 必须停用**（不能退化成日线形式，否则就是接飞刀） |
| **O4** | 板块/题材分类的口径（申万？概念？） | 主线判定完全依赖它 | 需固定一个口径，且不能中途更换 |
| **O5** | 3 槽位在 EXPAND 期可能长期空仓（信号不足） | 收益率被闲置拖累 | 接受；空仓也是一种仓位 |
| **O6** | 涨停制度仍在变（价格笼子、T+0 讨论） | 参数可能突然失效 | 制度变更时整体重估，不做局部修补 |

### 特别说明 O3

E2（低吸）的触发条件里有"开盘 30 分钟不创新低且站上均价"。这句话**没有日线替代品**。

如果只有日线数据，能构造的近似是"次日收盘价高于开盘价"——但那已经是**事后信息**，等于用未来数据做决策。这会让回测看起来很好、实盘完全无法执行。

> **所以：没有分时数据 = 没有 E2。** 宁可少一个引擎，不要一个假的引擎。

## 附：一句话总结

> 原文是一套**自洽但零安全边际**的经验系统。它的价值不在参数，在**结构**：
> 「先看情绪决定能不能做，再看题材决定做哪个方向，再看身位决定买谁，最后才决定用什么价位买」。
>
> 量化要做的事只有三件：
> ① 把这四步拆成互不干扰的层；
> ② 用滚动分位替代固定阈值；
> ③ **把"必须能成交"写进规则，而不是写进假设**。
